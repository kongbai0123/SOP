# 攝影機重新連線驗證

2026-10-19，在本機攝影機 0 上，先停止正式作業並中斷原程式連線，再以更新後的 `CameraSource`
讀取預設工站既有設定：1920×1080、60 FPS、MJPG，另套用已保存的影像參數及自動模式。
沒有執行 SOP 判定、寫入作業紀錄、修改工站設定或儲存影像。每次重新建立來源，預熱 3 秒、量測 8 秒後關閉。

FPS 採 `(N−1)/(最後時間戳−第一時間戳)`，而不是將驅動設定值當成實測。兩次結果均約 60 FPS，
但仍存在個別約 33 ms 的間隔。這是擷取及解碼完成的速率，不能證明每張都來自不同的感光曝光，
也不代表模型辨識或 GUI 繪製達到 60 FPS。DirectShow 無法讀回此設備的自動曝光模式，僅能確認驅動接受設定；
白平衡及對焦的模式均回報自動。

原始量測保存在本機 `.report-build/camera-reconnect/capture.json`。重現指令：

```powershell
.venv\Scripts\python.exe tools\check_camera_capture.py --index 0 --settings data\stations\ST001\app_settings.json --warmup 3 --duration 8 --reconnects 2 --output .report-build\camera-reconnect\capture.json
```

原連線流程沒有讀取保存的模式，只設定預設 1280×720。修正後於讀取執行緒啟動前套用工站設定，
依序設定解析度、FPS、FOURCC，再讀回最終協商結果。單獨調整格式群組的一項時會維持其餘可讀設定；
如果 FPS 或格式被重設，最多再嘗試一次 FPS → FOURCC。介面依最終讀回保存實際接受值，拒絕項保留先前偏好，
設定寫入失敗會通知使用者。前一個來源或工站的延遲回報不能覆寫目前工站。

「辨識上限」限制背景辨識／判定的最高頻率，0 為不限；攝影機讀取保持獨立，只保留最新影格。
等待在讀取前發生，不使用舊的辨識結果評估新的影格。慢於設定上限時不補跑積欠幀，也不額外等待完整一個週期。
正式作業期間不能變更此上限。降低取樣頻率可能漏掉短暫動作，需以現場 SOP 試跑驗證可接受的下限。
