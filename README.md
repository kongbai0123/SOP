# SOP 工序監控雛形

用攝影機 AI（Mask R-CNN、Faster R-CNN、YOLO 或 RT-DETR）即時判斷工人是否**依序**完成每道工序。工序數量與內容全部在軟體內編輯，不需要改程式。

目前測試版本：[v2026.10.16](https://github.com/kongbai0123/SOP/tree/v2026.10.16)。舊版 [v2026.10.13](https://github.com/kongbai0123/SOP/tree/v2026.10.13) 保留供回復。版本變更見 [更新紀錄](CHANGELOG.md)。

## 主要功能

- 在介面編輯 SOP 工序、完成條件、違規條件與逾時規則。
- 攝影機參數拉桿、解析度與 FPS 設定，搭配同視窗即時預覽。
- 支援 Mask R-CNN、Faster R-CNN、YOLO26 與 RT-DETR 模型包。
- 固定偵測區域，以及跟隨參考工件移動的作業區域。
- 多安裝位置：新增／複製、拖曳移動與縮放、改名、區域復原／重做，一鍵套用工序。
- 完成條件可選全部位置或任一位置；分開工序維持依序安裝。固定框可轉為跟隨本體，定位採逐幀光流與定期特徵校正。
- 執行監控提供「逐步／全開」兩種模式：逐步只輸出目前流程相關物件與位置，全開顯示全部；僅影響畫面、不影響背景判定。
- 依序判定作業、記錄 OK／NG、警報與完成截圖；警報當下也保留截圖。
- 違規條件可選「全部／任一」成立，並可獨立設定觀察時間與成立比例；可設定最短工時與跳步（順序錯誤）偵測。
- 作業員、工單、工件序號（可用條碼槍）與工站寫入每一輪紀錄；紀錄可依日期、結果、關鍵字篩選並匯出 CSV。

## 啟動

安裝環境後執行 `sop.bat`，批次視窗會短暫出現後立即關閉，程式在背景啟動。
本機若已建立 `SOP.lnk` 捷徑，也可雙擊捷徑啟動，不顯示黑色命令列視窗（捷徑不包含在儲存庫）。
關閉軟體介面就會結束程式，沒有額外安裝常駐 Windows 服務。

啟動時會先顯示前置視窗，列出介面元件、工作視窗等階段與已等待秒數。
進度條代表完成的啟動階段，並非預估剩餘時間。主介面開啟後，狀態列會接續顯示
模型載入、權重驗證、運算裝置選擇與預熱狀態，並以本機同一模型、同一執行環境的成功紀錄
估算剩餘時間。模型進度條只顯示完成百分比，旁邊顯示單一「預估剩餘 00:03」。
百分比以實際完成工作更新，預熱成功後才達到 100%；完成後自動隱藏載入提示。
剩餘時間依實測紀錄估算，顯示後只減少、不因切換工作而增加。
每個階段重新評估，首次啟動與
同一程序內切換模型分開記錄。沒有紀錄時顯示正在估算，
超出預估時間時明確提示，不延長倒數、不停在一秒或提前顯示零秒。
DLL 載入與 GPU 預熱無法回報內部進度，百分比可能等待工作完成才更新，剩餘時間並非完成保證。
紀錄保存在本機 `logs/model-load-times.json`；完成或失敗後自動結束載入提示。
AI 採獨立程序，啟動時就開始載入上次 SOP 使用的模型，與 Qt 介面同時準備。
介面程序不載入 PyTorch，無須等待 torch DLL 與 CUDA 初始化；AI 程序先載入 PyTorch，
並在同一程序完成模型預熱與後續辨識。影像透過共用記憶體傳遞，遮罩壓縮傳回，避免逐幀搬送完整影像。
關閉視窗會一併結束 AI 程序，載入尚未完成也可關閉。前置視窗在主介面就緒後關閉。

啟動日誌位於 `logs/startup.log`（自動輪替保存），包含啟動與模型載入的分段耗時。若 PyTorch 被 Windows 封鎖，
介面仍可使用，但 AI 辨識須待模型問題排除後才能使用。
模型載入或推論失敗時會記錄完整例外，供區分模型、驅動與應用程式控制問題。
捷徑使用目前專案的絕對路徑；搬移資料夾後請改用 `sop.bat` 或更新捷徑目標。

需要比較啟動時間時，可在開機後執行一次下列指令。它不開啟攝影機、不改寫設定或正式作業紀錄，
會測量主介面顯示、實際模型就緒與 1080p 影像推論耗時；重複執行屬於暖啟動測試。

```powershell
.venv\Scripts\python.exe tools\benchmark_startup.py --offscreen --output logs\startup-benchmark.json
```

加上 `--serial` 可比較原本先載入 torch 再建立介面的流程；冷啟動比較請分不同開機測量。

第一次安裝環境（已安裝過可略過）：

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pip install --no-deps ultralytics==8.4.150 ultralytics-thop ultralytics-platform
```

Git 儲存庫只包含程式、測試與範例設定，不包含作業紀錄、截圖、日誌、個人設定、
虛擬環境、模型權重、訓練資料與示範影片。首次使用請在「工序編輯 → 選擇模型…」
選取自己的模型包；範例的模型路徑若在本機不存在，請重新選擇。
`demo/demo_sop.mp4` 需自行提供，亦可使用 `tools/make_demo_video.py` 從本機圖片建立。
自訂 SOP 可能包含工件參考影像，預設不納入 Git；請另存新檔，保留範例為無影像的公開設定。

## 使用流程

第一次操作框選參考工件與 grip 作業區，可參考 [工件程序操作說明](docs/operation-guide/README.md)。框選時畫面暫停是正常狀態。

「工序編輯」中央為影像，影像下方為工件跟隨；左欄為專案、工序與下一輪設定，右欄為作業區域與試跑。
先在影像下方設定工件跟隨、右欄建立作業區域，再於左欄由上到下編輯各道工序與下一輪設定。只有凍結框選或編輯參考影像時，
畫面才會暫停；按「返回即時影像」恢復預覽。影像來源由標頭下方的影像來源列連線。

日常執行只需開啟已保存的 SOP 並放入車把手。「開始作業」始終可以操作，定位狀態只作提示。若尚未確認車把手位置，跟隨位置的條件會暫停累積，定位恢復後再重新累積，避免誤判。

若 Windows 應用程式控制封鎖 `cv2.pyd`，軟體會以編輯模式開啟，狀態列顯示原因。
此時可編輯／儲存 SOP 及查看既有紀錄，但攝影機、影片、工件定位與監控不可用。
若只封鎖 PyTorch DLL，AI 模型無法載入。修正啟動不代表解除系統封鎖；
需由電腦管理者處理可信套件及應用程式控制原則，再重新啟動。本程式不變更安全設定。

1. **連線影像**：上方工具列選「攝影機 N」或「影片檔…」→ 按「連線」
   - 沒有攝影機時可用 `demo\demo_sop.mp4`（由訓練圖片串成的測試影片）
   - 按「攝影機參數…」調整影像、解析度與 FPS，詳見下方說明。
2. **工序編輯**（標頭中央切換）
   - 工序收合為一行摘要，可上下比較；按「展開」編輯，每道工序列有展開／收合、上移、下移、複製、刪除、試跑
   - 在各工序內設定完成條件（物件、區域、數量、信心度、區域比例）、時間規則與違規條件
   - 按右欄「框選新區域」在畫面上拖曳出區域，讓條件只計算區域內的物件
   - 各工序的單幀預覽顯示目前影像是否符合條件；需累積時間的實際結果由試跑驗證
   - 標頭「儲存」或 `Ctrl+S` 儲存（覆寫時版本號自動 +1）
3. **執行監控** → 填寫作業員（工單、序號選填）→ 「開始作業」
   - 只評估目前這一道工序，完成後才進入下一道（嚴格依序）
   - 違規、超時、工時過短、順序錯誤會發出警報，該輪判定為 NG；警報面板持續閃爍，需按「確認警報」
   - 無條件的工序按「人工確認完成」；「跳過本工序（判 NG）」需再次確認，一律判 NG 並留下警報
   - 「停止作業」與「重新開始本輪」需再次確認，避免誤觸中止
   - 序號欄可用條碼槍掃描，按 Enter 後套用到下一輪
4. **作業紀錄**：每輪結果與作業資訊、所選輪次的版本與模型、各工序耗時、警報原因與確認資訊、定位暫停摘要、完成與警報當下的歷史截圖；
   可依日期、結果、關鍵字篩選，「匯出 CSV」輸出逐工序明細（Excel 可直接開啟）

## 作業紀錄資料庫

紀錄存於 `records/records.db`（SQLite，WAL 模式）與 `records/snapshots/`。資料庫以
`PRAGMA user_version` 標示結構版本，程式啟動時自動升級舊版資料庫，既有紀錄不需搬移。
程式異常結束時停在「進行中」的輪次，下次啟動會標記為「中斷」。寫入在獨立執行緒進行，
不影響影像處理；背景錯誤以非阻擋式視窗提示，相同訊息只顯示一次並累計次數。
工站名稱預設為電腦名稱，可在 `app_settings.json` 設定 `"station"`。

## 攝影機設定

連線攝影機後，按工具列的「攝影機參數…」。設定視窗同時顯示原始影像預覽，
可直接比較調整前後的效果；影片檔來源不提供硬體參數設定。

| 分頁 | 可調整內容 | 操作方式 |
|---|---|---|
| 解析度與 FPS | 解析度 | 選擇 640×480、1280×720、1920×1080、2560×1440、3840×2160，或輸入自訂寬高 |
| 解析度與 FPS | 每秒擷取影格數 | 拖曳拉桿、輸入 1～240 FPS，或按 15／24／30／60 快選 |
| 影像調整 | 亮度、對比、飽和度、銳利度、增益 | 直接拖曳拉桿，或用數值欄微調 |
| 影像調整 | 曝光、白平衡色溫、對焦 | 手動調整或選自動模式，需 DirectShow 後端與攝影機支援 |

1. 修改參數後，介面顯示待套用項目數量。
2. 按「套用 N 項變更」，只傳送修改項目，並列出要求值與設備回報值。
3. 若設備採用不同數值，會明確提示；失敗項目保留供修正後重試。
4. 按「捨棄未套用變更」可取消尚未送出的修改，不會改動攝影機。

常用解析度、FPS 與拉桿範圍只是操作選項，並非設備支援清單。
影像參數可透過數值欄延伸拉桿範圍；實際允許值、單位及自動模式支援程度由驅動決定。
回報 0 或 -1 也可能表示不支援，曝光負值不一定是錯誤。

預覽區分三種資訊：設備設定回報、實際畫面尺寸與擷取 FPS、程式處理 FPS。
提高攝影機 FPS 不保證 AI 辨識變快，處理速度仍受模型與硬體效能影響。
作業進行中禁止變更解析度與 FPS，請先停止作業，以免影像重新初始化影響判定。

已套用的設定不會因關閉視窗而復原；程式目前不保存攝影機參數。
重新連線後以設備當下狀態為準。硬體功能仍需在實際使用的攝影機上驗證。

## 判定規則

| 設定 | 說明 |
|---|---|
| 出現 | 區域內該物件數量 ≥ N |
| 消失 | 區域內該物件數量 = 0 |
| 條件需持續 + 成立比例 | 例如 1 秒內 80% 的畫面成立才算完成，用來過濾辨識閃爍 |
| 物件在區域內 | 物件遮罩或辨識框有 50% 以上落在區域內（`roi_overlap` 可在 JSON 調整） |
| 完成方式「任一」 | 任一位置成立即可；其他位置暫時出畫不會擋住，但全部無法確認時暫停累積 |
| 違規條件 | 「全部」或「任一」成立；觀察時間與成立比例預設沿用完成條件，可另設 |
| 最短工時 | 自動完成早於設定秒數 → 「工時過短」警報、該輪 NG（0 = 不檢查） |
| 偵測跳步 | 循環設定中啟用：後續工序（含「出現」條件）的條件提前成立 → 「順序錯誤」警報 |
| 重置條件 | 最後一道完成後，需等條件成立（例如工件消失）才開始下一輪；成立比例可設定；未設定則幾秒後自動開始 |

偵測跳步只適合後續工序條件不會被目前工序的完成狀態同時滿足的流程；例如第 3 道條件包含第 2 道條件時，請勿啟用。

```
  engine.py                判定引擎：嚴格依序、滑動時間窗、違規、超時、循環（純邏輯，可單元測試）
  model_bundle.py          讀取 Vision Workbench 模型包
  detector.py              TorchVision／YOLO／RT-DETR 推論
  inference_worker.py      獨立 AI 程序、共用影像與辨識結果傳遞
  camera_controls.py       攝影機硬體參數、解析度及 FPS 設定
  pipeline.py              背景執行緒：影像 → AI 程序 → 引擎 → 紀錄
  recorder.py              SQLite 紀錄與截圖（records/）
  ui/                      PySide6 介面
tests/                     工序、追蹤、模型包、攝影機、推論程序與啟動測試
tools/
  benchmark_startup.py     測量介面顯示、模型就緒與實際推論耗時
  check_model.py           檢查模型能否載入與偵測
  normalize_model_bundle.py 將舊版外層資料夾 ZIP 轉成標準模型包
  make_demo_video.py       用圖片串成測試影片
  simulate_sop.py          不開介面，用影片跑完整 SOP 並印出事件
```

## 常用指令

執行測試（不需要實體攝影機或模型權重）：

```bash
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

測試使用儲存庫原始的 `sops/example_sop.json`；若已覆寫成個人作業內容，
範例類別驗證可能失敗。建議透過「另存新檔」保存自己的 SOP。

```bash
.venv\Scripts\python.exe tools\simulate_sop.py sops\example_sop.json demo\demo_sop.mp4
```

若模型 ZIP 內含舊版外層資料夾，可先產生標準格式；原檔案不會被覆寫：

```bash
.venv\Scripts\python.exe tools\normalize_model_bundle.py <模型.zip>
```

## 工件定位與跟隨作業區域

1. 連線攝影機或影片，切換「工序編輯」，讓待作業工件清楚出現在畫面。
2. 在工件與區域區塊框選主要工件。畫面會暫停供框選；拖曳框選工件，盡量排除桌面背景、手與工具。
   工件必須有分散且清楚的紋理（圖案、文字、孔位等）；紋理不足時會提示重新選取。
3. 框選成功後使用參考影像，框出指定作業位置，在區域列直接命名如「左側壓合處」。可建立多個作業區。
4. 在各道工序的完成／違規條件中，選擇對應「區域」；同一區域也可供不同工序使用。
   點擊「返回即時影像」恢復即時畫面，觀察區域是否跟隨工件並測試條件。
   在即時畫面使用「框選新區域」建立的區域仍固定在畫面上。
5. 儲存 SOP，開始監控。參考影像內嵌於 SOP JSON，另存與搬移不需要另外複製圖片。

框選參考工件失敗時可直接重畫；隨時可按「返回即時影像」離開暫停／框選狀態。
若要判斷 grip 是否到達安裝位置，應框選安裝本體／治具為參考工件，
在安裝位置建立作業區，再設定該區出現 grip 的條件；到位不代表已鎖緊。

目前使用參考特徵定位，支援有紋理的剛性工件平移、等比縮放與平面旋轉。
取得有效定位的當幀即使用作業區；光流更新位置，並定期回到原始參考影像核對與校正。
定位在背景管線計算，編輯器、試跑與正式監控共用定位結果。
攝影機不必完全固定，但此版本不補償明顯透視變化、翻面、工件形變，
也不保證區分外觀相同的多個工件。請讓畫面內只有一個待定位工件，先用實際作業影片驗證。

定位失效或作業區超出畫面時，相關條件顯示無法確認，失效幀不可完成工序。
使用工件錨定區域的完成條件，最多可暫停累積 0.4 秒；恢復時須有有效定位，
且工件四角最大偏移不超過原對角線 5%。超時、移動過大、模型失效或作業區超出畫面時重新累積。
違規條件與輪次重置仍採嚴格判定。
漏檢／模型未就緒不會被當成消失。固定區域條件仍可獨立判定。
工序超時仍依實際經過時間計算；手動確認／跳過仍遵循原有 NG 規則。
執行中的無法確認與恢復事件會存入作業紀錄，完成截圖包含跟隨區域的框線。
重新框選參考工件之前需先移除舊的跟隨區域，避免舊位置誤綁到新的座標基準。
參考設定可在停止作業後修改，再開始新的作業輪次。

定位只確認作業位置；是否完成鎖緊、壓合等動作，仍取決於工序的模型辨識與完成條件。
舊版 SOP 可直接讀取，原有區域預設保持固定；儲存採 schema version 4（新欄位皆有預設值）。

### 更換辨識模型

在「工序編輯 → 選擇模型…」選擇新的模型包 `.zip`。目前支援 Vision Workbench 匯出的
`maskrcnn_resnet50_fpn`、Faster R-CNN、`yolo26n_detect`、`yolo26s_detect`、
`yolo26n_seg`、`yolo26s_seg` 與 `rt_detr_r50`。模型包可以直接放在 ZIP 根目錄，
也可以包在任意一層外部資料夾內；程式會自動尋找成對的 `model.json` 和 checkpoint。
第一次載入會把 checkpoint 解壓到模型旁的 `.extracted/` 資料夾並驗證 SHA-256。
若 SOP 使用了新模型沒有的類別，開始作業前會提示錯誤。

### 持續追蹤與校正

位置平滑採自適應卡曼；基準與驗證方式見 [追蹤實驗紀錄](docs/tracking-experiment.md)。

定位取得有效量測的當幀即輸出，不再等待連續三幀。光流每幀更新，每 15 幀回到參考影像核對；同幀兩個估計的區域角點最大距離，除以目前工件外接框對角線，超過 2% 時直接校正，小於門檻時平滑更新。這是估計間的偏差，不是真實位置誤差的保證。

參考核對暫時失敗時，每 5 幀重試；通過雙向與幾何驗證的實測光流最多延續 60 幀，避免無限累積漂移。部分遮擋可在剩餘特徵足夠時繼續追蹤；完全遮擋或量測失敗時停止位置相關完成判定，保留的橘框僅供顯示，恢復有效位置後立即重新累積完成條件。上述幀數指實際處理幀，不是攝影機設定 FPS。

## 單頁編輯與試跑

「工序編輯」中央為影像，左欄依自然設定順序排列工序，右欄為影像工具與試跑；不以內部分頁或工具選單切換內容。
工序收合時，滑鼠停在名稱列可查看全部規則；展開後條件的物件、區域、數量、信心度、區域比例、觀察時間與違規規則均直接可編輯。
改名、複製、刪除、上下移動與區域復原／重做都有明示文字按鈕，不依賴雙擊或滑鼠懸停。

每道工序顯示單幀預覽，單幀成立不代表工序完成。預覽與正式引擎共用 `evaluate_step()`，
正式執行會暫停累積的影格，預覽同樣顯示「無法判斷」。連線即時影像並載入模型後，
可試跑單一工序或完整流程。試跑使用設定快照與原有 `SOPEngine`，
不寫正式作業紀錄，也不控制正式監控；正式監控執行時須先停止才能試跑。
試跑會依序使用背景管線處理過的每一幀（與正式監控相同取樣），不受介面更新速度影響。
完整流程沿用既有重置條件／延遲重啟規則，可驗證下一輪；單步完成後自動停止。
人工工序可確認，但驗證區不能跳過有自動條件的工序。

修改設定、切換模型／來源、凍結畫面，或影像超過 3 秒未更新，會使試跑結果失效；
返回即時影像後重新開始試跑，才會使用目前草稿。上下捲動不會重置試跑。
循環區明示哪些參數生效，未使用的設定仍可見但停用，SOP 檔案格式不變。

介面保留可讀字級與輸入框高度。兩側欄寬依內容自動調整，長名稱不會被裁切；視窗太窄時右欄移到影像下方。
左右兩欄各自捲動、互不嵌套，避免多層捲軸互相搶走滾輪操作。
