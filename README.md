# SOP 工序監控雛形

用攝影機 AI（Mask R-CNN、Faster R-CNN、YOLO 或 RT-DETR）即時判斷工人是否**依序**完成每道工序。工序數量與內容全部在軟體內編輯，不需要改程式。

## 主要功能

- 在介面編輯 SOP 工序、完成條件、違規條件與逾時規則。
- 攝影機參數拉桿、解析度與 FPS 設定，搭配同視窗即時預覽。
- 支援 Mask R-CNN、Faster R-CNN、YOLO26 與 RT-DETR 模型包。
- 固定偵測區域，以及跟隨參考工件移動的作業區域。
- 多安裝位置：新增／複製、拖曳移動與縮放、改名、區域復原／重做，一鍵套用工序。
- 完成條件可選全部位置或任一位置；分開工序維持依序安裝。固定框可轉為跟隨本體，定位採逐幀光流與定期特徵校正。
- 執行監控提供「逐步／全開」兩種模式：逐步只輸出目前流程相關物件與位置，全開顯示全部；僅影響畫面、不影響背景判定。
- 依序判定作業、記錄 OK／NG、警報與完成截圖。

## 啟動

安裝環境後執行 `sop.bat`，批次視窗會短暫出現後立即關閉，程式在背景啟動。
本機若已建立 `SOP.lnk` 捷徑，也可雙擊捷徑啟動，不顯示黑色命令列視窗（捷徑不包含在儲存庫）。
關閉軟體介面就會結束程式，沒有額外安裝常駐 Windows 服務。

啟動時會先顯示前置視窗，列出 AI 執行環境、介面元件、工作視窗等階段與已等待秒數。
進度條代表完成的啟動階段，並非預估剩餘時間。主介面開啟後，狀態列會接續顯示
模型載入、權重驗證、運算裝置選擇與預熱狀態；完成或失敗後自動結束載入提示。
前置視窗採獨立短暫程序，不影響主程式的 PyTorch／Qt 載入順序，主介面就緒後會關閉。

啟動日誌位於 `logs/startup.log`（自動輪替保存），包含啟動與模型載入的分段耗時。若 PyTorch 被 Windows 封鎖，
介面仍可使用，但 AI 辨識須待模型問題排除後才能使用。
捷徑使用目前專案的絕對路徑；搬移資料夾後請改用 `sop.bat` 或更新捷徑目標。

第一次安裝環境（已安裝過可略過）：

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pip install --no-deps ultralytics==8.4.150 ultralytics-thop ultralytics-platform
```

Git 儲存庫只包含程式、測試與範例設定，不包含作業紀錄、截圖、日誌、個人設定、
虛擬環境、模型權重、訓練資料與示範影片。首次使用請在「工序編輯 → 選擇模型…」
選取自己的模型包；範例的模型路徑若在本機不存在，請重新選擇。
`demo/demo_sop.mp4` 需自行提供，亦可使用 `tools/make_demo_video.py` 從本機圖片建立。
自訂 SOP 可能包含工件參考影像，預設不納入 Git；請另存新檔，保留範例為無影像的公開設定。

## 使用流程

第一次操作框選參考工件與 grip 作業區，請先看 [grip 工件程序操作說明](docs/operation-guide/README.md)。說明內附逐步截圖，並解釋框選時畫面暫停是正常狀態。

「工序編輯」以左側工序流程為核心，清單在總覽、位置跟隨、安裝位置、工序條件與循環設定中都會保留；目前工序會清楚標示，雙擊可直接編輯。右側功能則依任務獨立顯示，一次只出現一組工具。一般使用者也可按「開始引導設定」，依畫面完成三步：框選完整車把手、連續建立安裝位置並配對物件、即時驗證後儲存。總覽使用乾淨影像；安裝位置只顯示位置框；工序條件才顯示與目前工序有關的辨識結果。

日常執行只需開啟已保存的 SOP 並放入車把手。「開始作業」始終可以操作，定位狀態只作提示。若尚未確認車把手位置，跟隨位置的條件會暫停累積，定位恢復後再重新累積，避免誤判。

1. **連線影像**：上方工具列選「攝影機 N」或「影片檔…」→ 按「連線」
   - 沒有攝影機時可用 `demo\demo_sop.mp4`（由訓練圖片串成的測試影片）
   - 按「攝影機參數…」調整影像、解析度與 FPS，詳見下方說明。
2. **工序編輯**分頁
   - 左側「工序清單」：新增／複製／刪除／上下移動工序
   - 右側「工序內容」：設定完成條件（物件、區域、數量、信心度）與選填的違規條件
   - 按「框選偵測區域」在畫面上拖曳出區域，讓條件只計算區域內的物件
   - 「即時」欄與畫面下方會顯示目前畫面是否符合條件，可邊看邊調
   - `Ctrl+S` 儲存（覆寫時版本號自動 +1）
3. **執行監控**分頁 → 「開始作業」
   - 只評估目前這一道工序，完成後才進入下一道（嚴格依序）
   - 違規條件成立（例如跳步）或超時會發出警報，該輪判定為 NG
   - 無條件的工序需按「手動確認」；跳過有條件的工序也會判定為 NG
4. **作業紀錄**分頁：每輪結果、各工序耗時、警報、完成當下的截圖

## 攝影機設定

連線攝影機後，按工具列的「攝影機參數…」。設定視窗同時顯示原始影像預覽，
可直接比較調整前後的效果；影片檔來源不提供硬體參數設定。

| 分頁 | 可調整內容 | 操作方式 |
|---|---|---|
| 解析度與 FPS | 解析度 | 選擇 640×480、1280×720、1920×1080、2560×1440、3840×2160，或輸入自訂寬高 |
| 解析度與 FPS | 每秒擷取影格數 | 拖曳拉桿、輸入 1～240 FPS，或按 15／24／30／60 快選 |
| 影像調整 | 亮度、對比、飽和度、銳利度、增益 | 直接拖曳拉桿，或用數值欄微調 |
| 影像調整 | 曝光、白平衡色溫、對焦 | 手動調整或選自動模式，需 DirectShow 後端與攝影機支援 |

1. 修改參數後，介面顯示待套用項目數量。
2. 按「套用 N 項變更」，只傳送修改項目，並列出要求值與設備回報值。
3. 若設備採用不同數值，會明確提示；失敗項目保留供修正後重試。
4. 按「捨棄未套用變更」可取消尚未送出的修改，不會改動攝影機。

常用解析度、FPS 與拉桿範圍只是操作選項，並非設備支援清單。
影像參數可透過數值欄延伸拉桿範圍；實際允許值、單位及自動模式支援程度由驅動決定。
回報 0 或 -1 也可能表示不支援，曝光負值不一定是錯誤。

預覽區分三種資訊：設備設定回報、實際畫面尺寸與擷取 FPS、程式處理 FPS。
提高攝影機 FPS 不保證 AI 辨識變快，處理速度仍受模型與硬體效能影響。
作業進行中禁止變更解析度與 FPS，請先停止作業，以免影像重新初始化影響判定。

已套用的設定不會因關閉視窗而復原；程式目前不保存攝影機參數。
重新連線後以設備當下狀態為準。硬體功能仍需在實際使用的攝影機上驗證。

## 判定規則

| 設定 | 說明 |
|---|---|
| 出現 | 區域內該物件數量 ≥ N |
| 消失 | 區域內該物件數量 = 0 |
| 條件需持續 + 成立比例 | 例如 1 秒內 80% 的畫面成立才算完成，用來過濾辨識閃爍 |
| 物件在區域內 | 物件遮罩或辨識框有 50% 以上落在區域內（`roi_overlap` 可在 JSON 調整） |
| 重置條件 | 最後一道完成後，需等條件成立（例如工件消失）才開始下一輪；未設定則幾秒後自動開始 |

## 專案結構

```
main.py                    啟動入口
sops/                      SOP 設定檔（JSON）
sop_app/
  sop_schema.py            SOP 格式、讀寫、檢查
  conditions.py            單一畫面的條件判斷（物件＋區域＋數量＋信心度）
  engine.py                判定引擎：嚴格依序、滑動時間窗、違規、超時、循環（純邏輯，可單元測試）
  model_bundle.py          讀取 Vision Workbench 模型包
  detector.py              TorchVision／YOLO／RT-DETR 推論
  camera_controls.py       攝影機硬體參數、解析度及 FPS 設定
  pipeline.py              背景執行緒：影像 → 偵測 → 引擎 → 紀錄
  recorder.py              SQLite 紀錄與截圖（records/）
  ui/                      PySide6 介面
tests/                     判定引擎、工件定位、模型包與攝影機設定測試
tools/
  check_model.py           檢查模型能否載入與偵測
  normalize_model_bundle.py 將舊版外層資料夾 ZIP 轉成標準模型包
  make_demo_video.py       用圖片串成測試影片
  simulate_sop.py          不開介面，用影片跑完整 SOP 並印出事件
```

## 常用指令

執行測試（不需要實體攝影機或模型權重）：

```bash
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

測試使用儲存庫原始的 `sops/example_sop.json`；若已覆寫成個人作業內容，
範例類別驗證可能失敗。建議透過「另存新檔」保存自己的 SOP。

```bash
.venv\Scripts\python.exe tools\simulate_sop.py sops\example_sop.json demo\demo_sop.mp4
```

若模型 ZIP 內含舊版外層資料夾，可先產生標準格式；原檔案不會被覆寫：

```bash
.venv\Scripts\python.exe tools\normalize_model_bundle.py <模型.zip>
```

## 工件定位與跟隨作業區域

1. 連線攝影機或影片，切換「工序編輯」，讓待作業工件清楚出現在畫面。
2. 按「① 框選參考工件」。畫面會暫停供框選，並非當機；拖曳框選工件，盡量排除桌面背景、手與工具。
   工件必須有分散且清楚的紋理（圖案、文字、孔位等）；紋理不足時會提示重新選取。
3. 框選成功後自動進入「② 編輯作業區（參考影像）」模式並啟用下一次框選，
   在工件內框出指定作業位置，命名如「左側壓合處」。可建立多個作業區。
4. 在各道工序的完成／違規條件中，選擇對應「區域」；同一區域也可供不同工序使用。
   點擊「③ 返回即時測試」恢復即時畫面，觀察區域是否跟隨工件並測試條件。
   在即時畫面使用「框選偵測區域」建立的區域仍固定在畫面上。
5. 儲存 SOP，開始監控。參考影像內嵌於 SOP JSON，另存與搬移不需要另外複製圖片。

框選參考工件失敗時可直接重畫；隨時可按「③ 返回即時測試」離開暫停／框選狀態。
按「操作說明」可在介面內查看三步教學與 grip 安裝範例。
若要判斷 grip 是否到達安裝位置，應框選安裝本體／治具為參考工件，
在安裝位置建立作業區，再設定該區出現 grip 的條件；到位不代表已鎖緊。

目前使用參考特徵定位，支援有紋理的剛性工件平移、等比縮放與平面旋轉。
連續三個有效影像定位穩定後才使用作業區；每次以原始參考影像重新定位，避免累積漂移。
攝影機不必完全固定，但此版本不補償明顯透視變化、翻面、工件形變，
也不保證區分外觀相同的多個工件。請讓畫面內只有一個待定位工件，先用實際作業影片驗證。

定位失效或作業區超出畫面時，相關條件顯示無法確認並清空累積時間；恢復後重新累積。
漏檢／模型未就緒不會被當成消失。固定區域條件仍可獨立判定。
工序超時仍依實際經過時間計算；手動確認／跳過仍遵循原有 NG 規則。
執行中的無法確認與恢復事件會存入作業紀錄，完成截圖包含跟隨區域的框線。
重新框選參考工件之前需先移除舊的跟隨區域，避免舊位置誤綁到新的座標基準。
參考設定可在停止作業後修改，再開始新的作業輪次。

定位只確認作業位置；是否完成鎖緊、壓合等動作，仍取決於工序的模型辨識與完成條件。
舊版 SOP 可直接讀取，原有區域預設保持固定；儲存採 schema version 2。

### 更換辨識模型

在「工序編輯 → 選擇模型…」選擇新的模型包 `.zip`。目前支援 Vision Workbench 匯出的
`maskrcnn_resnet50_fpn`、Faster R-CNN、`yolo26n_detect`、`yolo26s_detect`、
`yolo26n_seg`、`yolo26s_seg` 與 `rt_detr_r50`。模型包可以直接放在 ZIP 根目錄，
也可以包在任意一層外部資料夾內；程式會自動尋找成對的 `model.json` 和 checkpoint。
第一次載入會把 checkpoint 解壓到模型旁的 `.extracted/` 資料夾並驗證 SHA-256。
若 SOP 使用了新模型沒有的類別，開始作業前會提示錯誤。
